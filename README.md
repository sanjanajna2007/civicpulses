# CivicPulse AI

AI-assisted civic complaint management. React + TypeScript + Tailwind CSS on the front end; Supabase (PostgreSQL, Auth, Storage, Row Level Security) as the backend.

## Setup
1. Create a free project at https://supabase.com.
2. Open **SQL Editor**, paste all of `supabase/schema.sql`, and run it. This creates the tables (`profiles`, `complaints`, `notifications`, `departments`, `status_history`), triggers, RLS policies, public RPC functions and the `complaint-images` storage bucket.
3. (Optional, for quick testing) **Authentication > Providers > Email**: turn off "Confirm email".
4. Copy `.env.example` to `.env` and fill in **Project URL** and **anon public key** (Project Settings > API). Never use the `service_role` key in this app.
5. Run `npm install` then `npm run dev` and open the printed URL.
6. Sign up in the app, then make yourself admin in the SQL Editor:
   `update profiles set role='admin' where id=(select id from auth.users where email='you@example.com');`
   Sign out and in again.

## Structure
```
supabase/schema.sql      tables, triggers, RLS, RPCs, storage policies
src/lib/                 supabase client, auth context, ai.ts (rules + similarity), types
src/pages/               Home, Report, Track, Admin, Insights, Login
src/components/          ui.tsx (cards, charts), HotspotMap.tsx (Leaflet + OpenStreetMap)
```

## How it works
- **Home / Insights**: read real rows through the `public_complaints()` function, which returns no user ids.
- **Report** (login required): optional photo goes to Storage (`<user-id>/<file>`), its public URL is saved in `complaints.image_url`. The complaint ID (`CP-2026-1001`…) is generated by the database.
- **Track**: anyone can look up an ID via `track_complaint()`, which returns limited fields and status history.
- **Admin**: role-checked via `profiles.role`; filter, assign a department, change status. Each status change writes `status_history` and a `notifications` row (database trigger). Citizens see them under the 🔔 bell.
- **Security**: RLS restricts citizens to their own complaints and notifications; only admins can update complaints; users cannot change their own role; uploads are limited to the user's own folder.

## AI: what is real
| Feature | Method |
|---|---|
| Category and priority + explanation | **Rule-based** keyword scoring (`src/lib/ai.ts`). Not a trained model. |
| Duplicate check on submission | **PostgreSQL `pg_trgm`** trigram similarity (statistical text matching). |
| Duplicate pairs and "why similar" in Insights | **Jaccard word overlap** plus same location/category, computed in the browser. |
| Hotspots, trends, distributions | Counts over real database rows. |

No machine-learning model, neural network or LLM is used, and photos are stored but not analysed.

## Known limitations
- Citizens must have an account to submit (needed for notifications and RLS).
- Notifications are in-app only (polled every 20 s); no email/SMS.
- Hotspot map shows only complaints that have coordinates ("Find on map" uses OpenStreetMap Nominatim; "Use my GPS" uses the browser).
- `public_complaints()` is read on every Home/Insights load; add pagination/aggregation for very large datasets.
- Complaint descriptions are visible to anyone via Insights and duplicate checks. Tell citizens not to include personal details.
